# Дизайн 1 — генератор и проверка, этап 8

Статический HTML, CSS и vanilla JS. Для сборки достаточно Python 3. Всё содержание и все панели уже находятся в HTML; сайт работает через file:// и GitHub Pages. Контакты не отправляются и не сохраняются.

```sh
python3 tools/d1/build.py
python3 tools/d1/check8.py --static
python3 tools/d1/check.py
python3 tools/d1/screens8.py
```

Полные проверки/снимки используют только инструменты разработки Playwright и Pillow. Нужны установленные Chromium, Firefox и WebKit с системными зависимостями. В данном окружении Firefox требует запуска вне изоляции графического буфера. Временные браузеры и библиотеки в репозиторий не включены; `engines7.py` умеет использовать подготовленный `/tmp/pw7`, если он есть. На обычной машине установите браузеры стандартной командой `python3 -m playwright install --with-deps chromium firefox webkit`. Сам сайт этих зависимостей не использует.

## Данные и шаблоны

- `data.json` — страны, предложения, общие тексты, восемь `rest_pages`, исходники и контрольные суммы утверждённых разделов.
- `rest.py` — один шаблон восьми разделов: обложка → виды → страны → подборки → проверки → FAQ → конечная форма. Порядок хранится в `section_order`.
- `import_rest7.py` — однократный импорт восьми `razdel-*.md` из указанной папки: `python3 tools/d1/import_rest7.py <папка>`. Перед обычной сборкой импорт не требуется.
- `stage6.py` — общая шапка/подвал, единые формы трёх видов, темы, главная, услуги, компания и предложения. Числа в имени обозначают происхождение модуля; CSS этапов больше нет.
- `country.py` — единый шаблон девяти стран по схеме 12.11. Египет — тексты редакции 3; `import_country8.py` явно импортирует исходник, `read_schema8.cjs` извлекает только литералы данных. Обычная сборка не требует Node или сети. Пустые справочные блоки других стран скрываются.
- `styles.py` — единый набор CSS и preload шрифтов на сгенерированных страницах.
- `brand.py` — дизайн-система и актуальный DESIGN.md.

Сначала меняйте данные/шаблон, затем собирайте HTML и коммитьте оба. Шаблоны не читают страницы из соседних дизайнов как новый источник содержания. Источники фото/бренда остаются в `img/sources.json`; новые реальные фотографии надо добавить туда с лицензией. У неизвестных отелей, программ, маршрутов и лиц — аккуратные условные поля, без выдуманных фактов.

## Контекст и состояние

Форма строится одной функцией `form()`, семь скрытых полей: topic, page и пять UTM. Подбор, предложение и услуга различаются только набором полей. Телефон и пустое обязательное согласие проверяются локально; после результата поля очищаются. Без JS fieldset заблокирован, доступен телефон.

Контекст раздела: `holiday:<slug>`, затем `:type:<index>`, `:country:<slug>` или `:hotel:<id>`. У маршрутов используется тот же типизированный контекст. Сообщение содержит утверждённый текст раздела, выбранный контекст и только разрешённые поля поездки. Телефон и скрытые поля в сообщение не входят; аналитика не содержит контактов и свободного текста.

`?country=…` сохраняет вкладку. В `history.state` лежат только открытые id и позиция прокрутки. Нет localStorage и сохранения формы. На возврате ждём шрифты, сохраняем раскрытые пункты и восстанавливаем позицию; в разделе отключена автоматическая привязка к меняющейся высоте.

## Стили и совместимость

`tokens.css` — единственный источник размеров текста, цветов и базовых отступов. Далее fonts/base/layout/components/header и файлы home/country/rest/offers. Основной текст 16/17 px, вводный 20, вторичный 14, служебный минимум 13, интерфейс 16; размеры записаны через rem/clamp. Мелкая антиква заменена Manrope, небольшие заголовки — от 22 px весом 500.

Есть vh перед svh/dvh, префикс backdrop-filter, классовые запасные состояния :has(), запасное управление фокусом без inert, нативные dialog. ES5-файл legacy.js содержит простую заметку для document.documentMode. Пиксельный размер текста только у этой изолированной заметки: IE не поддерживает переменные.

## Отчёты

- `check8.py`: независимое сравнение утверждённых Markdown-параграфов/ячеек, ссылки, формы, SEO, JSON-LD, детерминированность, 41 страница × 10 ширин × 3 движка, клавиатура, вкладки, окна, контекст и возврат.
- `hero_check.py`: 20 измерений зазора заголовка/описания и позиции кнопки.
- `contrast5.py`: контраст сплошных фонов и выборки поверх фотографий; обычный текст 4,5:1, крупный 3:1. Имя сохранено по требованию прежнего задания.
- `panels7.py`: 18 состояний панели на 360/390 в трёх движках — высота ≤64 px, текст 16 px, цели ≥44 px.
- `screens8.py`: 40 адресов × 2, четыре кадра шапки и два кадра главной в WebKit; JPEG 75. Галерея и SCREENS_QA.json обновляются, устаревшие снимки удаляются.

Требуемые значения для публикации собраны в CHECKLIST.md и otdyh/CHECKLIST.md. Справочные климатические/визовые сведения и новые отели без подтверждения не придумывать. Другие дизайны и общие активы не изменять.

## Приёмка этапа 8

`check8.py` проверяет дословные тексты Египта из исходного HTML, массивы климата и все ячейки таблиц; неизменность утверждённых текстов отдыха с разрешённым удалением точки/двоеточия только из заголовков; воспроизводимость HTML, ссылки, JSON-LD, три состояния блока предложений. Затем проходит все страницы × 8 ширин × 3 движка, измеряет шапку и крошки, проверяет ширину блоков, полную надпись месяца, видимость кнопок обложки и сценарии Египта. Сервер отдаёт папку `docs`, включая общие активы. `offers8.py` проверяет переключатель и пустой каталог без изменения исходных данных.

`QA8.json` и `QA8.md` содержат результаты и объяснения узких элементов, `SCREENS_QA.json` — параметры снимков. Снимки — JPEG 75, 390 px с плотностью 2, 1440 px, дополнительные кадры шапки/крошек/раскрытого курорта/таблицы. Перед снимком включается reduced-motion, страница прокручивается вниз и обратно, загружаются изображения и шрифты, затем выдерживается 500 мс. `screens8.py` обновляет всю галерею.

## Этап 9

Текущая приёмка — `python3 tools/d1/check9.py` (или `check.py` для неё и дополнительных прежних проверок). Она включает статическую проверку этапа 8, контроль неизменности данных, геометрию всех страниц, интервалы шапки, выравнивание всех доступных форм (включая окна), цены, полноту карточных рядов, раскрытие Хургады и фикстуры появления климата. `cardinality9.py` проверяет наборы 1–6 и их динамическое изменение; вызывается также из check9. `screens9.py` обновляет только запрошенные состояния и помечает остальные снимки архивом этапа 8. Полный прогон screenshots8 продолжает быть доступен, но не нужен для целевых снимков этапа 9.

`css/grids.css` — общая геометрия карточных коллекций. Карточки считаются по видимым соседним элементам CSS `:has`; JS не генерирует содержимое и не вычисляет SEO-разметку. В условном климате `country.has_climate` считает данные числовыми, включая ноль, исключая null и bool. Источник текстов и текущая бизнес-логика не менялись.

## Этап 10

Текущая проверка: `python3 tools/d1/check10.py` (или `check.py`). Новый раздел задаётся отдельной записью `cruise_page` и использует тот же `rest.py`; предыдущие `rest_pages` не менялись. `read_cruises10.cjs` извлекает только литералы источника для независимой проверки текста, обычная сборка по-прежнему требует только Python stdlib.

`stage10_preservation.json` содержит отпечатки предыдущих данных и HTML с нормализацией только разрешённых ссылок. Это проверяет границы задачи без зависимости от временных папок или доступности истории Git. Проверяются все ссылки/ресурсы, данные из схемы, воспроизводимость, 24 сочетания новой страницы/движка/ширины и шесть функциональных прогонов. `screens10.py` обновляет только круизы и окно с выбранным форматом, остальные изображения галереи явно помечены архивом. Реальной отправки формы нет.

## Текущая приёмка — этап 11

`python3 tools/d1/build.py` собирает 43 адреса, включая новую страницу реквизитов. `python3 tools/d1/check.py` запускает check11.py и controls11.py: ссылки/якоря/изображения, SEO, JSON-LD, точные реквизиты, воспроизводимость, числовые настройки, select, геометрию карточек/значков/крошек, независимое раскрытие и окна. Девять ширин 360–2560 в Chromium, Firefox, WebKit. `content11-lock.json` фиксирует хеши всех ранее существовавших данных контента; новое поле requisites и техническая палитра проверяются отдельно. `contrast5.py` измеряет фактический контраст; имя историческое.

`python3 tools/d1/screens11.py` снимает актуальные 42 нетехнических адреса на 390/1440, четыре страницы на 2560 и детали этапа 11. Полный комплект — screens/review/, детали и помеченный архив — screens/pages/. Для пересъёмки только технического гида: `screens11.py --page styleguide.html`.

`stage11.py` отвечает за новую разметку реквизитов, отзывов и навигации. PDF URL хранятся в data.json → requisites.documents[].url: пустой URL открывает именованное окно, заполненный — PDF с target=_blank и rel=noopener. Никаких запросов/сохранения пользовательских данных не добавлено.
